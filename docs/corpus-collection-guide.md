# 语料收集操作说明（RAG 知识库 · 毕设 Demo）

本文档给「负责收集资料的人」逐步照着做即可，完成后把 **`corpus` 文件夹**整体交给开发同学接入向量检索。

---

## 一、我们要做什么

- 收集一批 **公开、可复制文字** 的 **中文医学健康科普**（不是病历、不是处方药说明书全文）。
- 统一保存为 **UTF-8 的 `.txt` 文件**，并按下文规则 **命名**、**写文件头**。
- 总量控制在小 Demo 规模：**全文合计约 1.5～3 万字**，约 **12～25 个文件**。

---

## 二、从哪里复制（允许的来源类型）

请只从下面类型的页面 **手工复制正文**（不推荐一上来全网爬虫，合规与排版都难控）。

| 类型 | 说明 | 如何找到文章 |
|------|------|----------------|
| **政府与公共卫生机构** | 卫健委、疾控中心、健康中国等栏目里的科普 | 搜索：`site:nhc.gov.cn 科普`、`健康中国 高血压 科普` |
| **公立医疗机构官网** | 「患者教育」「就医指南」「健康科普」栏目 | 搜索：`协和医院 健康科普 胸闷`、`人民医院 患者教育 咳嗽` |
| **医学学会 / 基金会科普** | 公开发布的疾病介绍（非付费全文盗版） | 搜索：`中华医学会 科普 消化系统` |
| **国际组织中文版** | WHO 等公开健康主题页（中文） | 搜索：`世界卫生组织 中文 咳嗽` |

**不要使用的来源：**

- 扫描版 PDF、图片里的文字（不可稳定复制）。
- 论坛闲聊帖、未署名传言、偏方。
- 含有 **真实患者姓名、住院号、手机号** 的内容。
- 盗版整本书 PDF、明显侵权转载。

每篇文章请在收集时 **记下网页标题 + 完整链接**（或书名+章节），后面要写进文件头和汇总表。

---

## 三、电脑上怎么建文件夹

1. 在桌面（任意位置）新建文件夹，命名为：**`corpus`**
2. 在 `corpus` 里先新建一个空文件：**`meta_sources.txt`**（汇总清单，见第七节）
3. 其余科普正文各自保存为独立的 `.txt` 文件，放在 **`corpus` 根目录**（不要多层子目录）

最终结构示例：

```text
corpus/
  meta_sources.txt
  cardiovascular_01.txt
  cardiovascular_02.txt
  respiratory_01.txt
  respiratory_02.txt
  digestive_01.txt
  digestive_02.txt
  general_01.txt
  ...
```

---

## 四、文件如何命名（必须遵守）

**规则：** 全部 **小写英文** + **下划线** + **两位序号** + **`.txt`**

**前缀（表示大致方向，对应后续检索偏好）：**

| 前缀 | 含义 | 最少文件数 |
|------|------|------------|
| `cardiovascular_` | 心血管相关科普（胸闷、胸痛、心悸、血压等） | **至少 2 个** |
| `respiratory_` | 呼吸相关科普（咳嗽、呼吸困难、发热伴呼吸道症状等） | **至少 2 个** |
| `digestive_` | 消化相关科普（腹痛、腹泻、反酸等） | **至少 2 个** |
| `general_` | 泛健康 / 无法严格归入上面三类的科普 | **至少 1 个** |

**序号：** `01`、`02`、`03`… 同一前缀内递增即可。

**合法示例：**

- `cardiovascular_01.txt`
- `respiratory_02.txt`
- `general_01.txt`

**不要用：** 中文文件名、空格、`CV-1.txt` 这种混合格式。

---

## 五、每个 `.txt` 里面要粘贴什么（模板）

每个文件 **最上面必须是固定 4 行「文件头」**，**空一行**，再写正文。

### 5.1 直接复制下面模板，改括号里的内容

```text
#SOURCE_TITLE: （填网页文章标题，或章节标题）
#SOURCE_URL_OR_REF: （填完整 https:// 链接；若来自纸质书则写：书名 + 章节名）
#DOMAIN_HINT: cardiovascular
#LANG: zh-CN

（从这里开始粘贴正文：必须是科普叙述，见第六节）
```

### 5.2 `#DOMAIN_HINT` 只能填下面之一（四选一）

| 填写值 | 说明 |
|--------|------|
| `cardiovascular` | 内容与心、血管、胸闷胸痛心悸血压等相关 |
| `respiratory` | 内容与咳嗽、感冒、肺炎、呼吸困难等相关 |
| `digestive` | 内容与腹痛、腹泻、反酸等相关 |
| `general` | 泛健康、就医常识、或难以归入上面三类 |

### 5.3 正文应该是什么样子的内容

**建议包含这些块（用自然段写即可，不必加小标题）：**

- 这种现象 **常见于什么情况**（通俗说明）
- **伴随哪些表现时要多加留意**
- **什么情况下建议就医**、大致 **挂哪类科室**（表述笼统即可，勿下个体诊断）
- **日常注意事项**（休息、观察等，勿写具体药名剂量）

**单文件字数：** 约 **800～2500 字**（中文）。太短检索不灵，太长不必。

**避免：**

- 大段药品剂量表、处方组合
- 「你一定是××病」式断言
- 广告、引流联系方式

## 六、如何用记事本 / VS Code 正确保存为 UTF-8

1. 打开 **VS Code**（推荐）或系统记事本。
2. 粘贴：**文件头 4 行 → 空一行 → 正文**。
3. **另存为**：
   - 文件名：按第四节命名，例如 `digestive_01.txt`
   - 编码：**UTF-8**（VS Code 右下角点击编码 → “通过编码保存” → 选 UTF-8）
4. 关闭前确认：**文件头 `#SOURCE_TITLE` 等仍完整**，正文无乱码。

## 七、`meta_sources.txt` 怎么写（必填）

在 **`corpus/meta_sources.txt`** 里，**每行一条**，对应一个 txt 文件，格式：

```text
文件名 | 来源标题 | 链接或参考书目
```

**示例：**

```text
cardiovascular_01.txt | 胸闷气短常见于哪些情况 | https://example-hospital.gov.cn/xxx
respiratory_01.txt | 咳嗽的家庭观察与何时就医 | https://example.gov.cn/xxx
```

若一书摘录无链接：

```text
digestive_01.txt | 《内科学》节选-腹痛概述 | 人民卫生出版社第X版第X章（页码）
```

## 八、提交前的自检清单（收集人完成打勾）

- [ ] 只有 **`.txt`**，没有 PDF / Word / 图片
- [ ] 所有文件均为 **UTF-8**，打开无乱码
- [ ] 每个文件均有 **4 行文件头** + 空行 + 正文
- [ ] 命名符合第四节规则（小写 + 前缀 + 序号）
- [ ] **cardiovascular** ≥2、`respiratory` ≥2、`digestive` ≥2、`general` ≥1
- [ ] 总字数大约 **1.5～3 万字**（不必精确，目测即可）
- [ ] **`meta_sources.txt`** 已填写完整
- [ ] 无个人隐私、无偏方广告、无整页复制无关导航菜单文字

将整个 **`corpus` 文件夹**打包为 **`corpus.zip`** 发送，或拷贝到项目仓库中的 **`corpus/`** 目录（若仓库需忽略大文件，由开发配置 `.gitignore`）。

## 十、常见问题

**Q：一篇文章太长怎么办？**  
A：拆成两篇同前缀不同序号，例如 `respiratory_01.txt`、`respiratory_02.txt`，各自保留完整文件头，`#SOURCE_TITLE` 可写成「原标题（上）」「原标题（下）」。

**Q：网页里有大量侧边栏、推荐阅读怎么办？**  
A：只复制 **正文主段落**，不要复制全页导航、评论区。

**Q：可以用 ChatGPT 生成正文吗？**  
A：Demo 若导师允许可作为补充，但须在 `meta_sources.txt` 标明「自拟科普草稿」，且内容仍需人工核对，避免医学错误；**论文引用来源**建议以公开网页/书籍为主更稳妥。
